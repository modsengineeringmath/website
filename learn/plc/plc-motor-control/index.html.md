# ควบคุมมอเตอร์ด้วย PLC: DOL กลับทางหมุน สตาร์-เดลต้า รายการ I/O การต่อสาย อินเตอร์ล็อกฮาร์ดไวร์ และการตรวจสอบป้อนกลับคอนแทกเตอร์

THภาษาไทยENEnglish

// บทที่ 22.6 · PLC · Motor Control with a PLC


เมื่อย้ายลอจิกจากตู้รีเลย์มาไว้ใน PLC สิ่งที่ได้คือความยืดหยุ่น การแสดงสถานะ และการตรวจจับความผิดปกติ แต่สิ่งที่ต้องไม่เสียไปคือความปลอดภัยของวงจรเดิม หน้านี้แบ่งชัดเจนว่าอะไรอยู่ในซอฟต์แวร์ อะไรต้องอยู่ในฮาร์ดแวร์ และให้โปรแกรมที่ใช้ได้จริงสำหรับวงจรมอเตอร์ทั้งสามแบบ

สรุปใน 30 วินาที

- คงไว้ในฮาร์ดแวร์: หยุดฉุกเฉินผ่านรีเลย์เซฟตี้ · โอเวอร์โหลด 95-96 · อินเตอร์ล็อก NC + กลไก

- PLC ทำ: ล็อกตัวเอง ลำดับ ไทเมอร์ ตรวจป้อนกลับ แจ้งเตือน นับชั่วโมง

- ป้อนกลับ: $\text{Fault} = \text{TON}(\text{Cmd} \oplus \text{FB},\ 0.5\text{–}2\ \text{s})$

- สตาร์-เดลต้า: Y ก่อน → K1 → ครบเวลา → Y ปล่อย → ช่วงตาย → Δ

## แบ่งหน้าที่: ฮาร์ดแวร์กับซอฟต์แวร์ พื้นฐาน

| หน้าที่ | ที่ไหน | เหตุผล |

| หยุดฉุกเฉิน | รีเลย์เซฟตี้/safety PLC ตัดไฟคอยล์ + PLC อ่านสถานะ | ต้องทำงานแม้ PLC มาตรฐานเสียหรือถูกแก้โปรแกรม |

| โอเวอร์โหลด | 95-96 อนุกรมคอยล์ + 97-98 เข้า PLC | ตัดได้แม้ PLC ค้าง และแสดงสาเหตุได้ |

| อินเตอร์ล็อกกันลัดวงจร | NC ช่วย + กลไก + ในโปรแกรม | เอาต์พุตทรานซิสเตอร์ลัดค้างหรือการ force ต้องไม่ทำให้ลัดวงจร |

| ล็อกตัวเอง ลำดับ ไทเมอร์ | โปรแกรม | แก้ไขง่าย ตั้งค่าจาก HMI |

| ตรวจคอนแทกเตอร์ค้าง/ไม่ดูด | โปรแกรม + หน้าสัมผัสป้อนกลับ | ตรวจได้เฉพาะเมื่อมีสมองกล |

## DOL ด้วย PLC และการตรวจป้อนกลับ พื้นฐาน

| แอดเดรส | อุปกรณ์ | ชนิด |

| I0.0 | -S0 STOP | NC (1 = ปกติ) |

| I0.1 | -S1 START | NO |

| I0.2 | -F2 97-98 หรือ 95-96 ช่วย | NC (1 = ปกติ) |

| I0.3 | -K1 13-14 ป้อนกลับ | NO |

| Q0.0 | -K1 คอยล์ (ผ่าน 95-96) | รีเลย์หรือรีเลย์ต่อกลาง |

| Q0.1 / Q0.2 | ไฟเดิน / ไฟผิดปกติ | — |

M1 Run command คำสั่งเดิน

$$\text{Cmd} = I0.0\cdot I0.2\cdot\overline{\text{Fault}}\cdot(I0.1 + \text{Cmd})$$

M2 Feedback discrepancy ตรวจความไม่ตรงกันของป้อนกลับ

$$\text{Fault} \leftarrow \text{TON}(\text{Cmd} \oplus \text{FB},\ t_{fb}) \qquad t_{fb} \approx 0.5\text{–}2\ \text{s}$$

กรณีที่ M2 จับได้: สั่งแล้วไม่ดูด (ฟิวส์คอยล์ขาด คอยล์ขาด 95-96 เปิด) และไม่ได้สั่งแต่ยังดูด (หน้าสัมผัสเชื่อมติด เอาต์พุตค้าง) — กรณีหลังอันตราย ต้องแจ้งเตือนและตัดด้วยอุปกรณ์ต้นทาง

## กลับทางหมุนด้วย PLC กลาง

M3 Software interlock อินเตอร์ล็อกในโปรแกรม

$$Q_F = \overline{S0}\,\overline{OL}\,(S_F + Q_F)\,\overline{S_R}\,\overline{Q_R}\,\overline{FB_R} \qquad Q_R = \overline{S0}\,\overline{OL}\,(S_R + Q_R)\,\overline{S_F}\,\overline{Q_F}\,\overline{FB_F}$$

เพิ่ม $\overline{FB}$ ของอีกทิศ (ป้อนกลับจากคอนแทกเตอร์จริง) ทำให้โปรแกรมไม่สั่งทิศใหม่จนกว่าคอนแทกเตอร์เดิมปล่อยจริง และนิยมเพิ่มไทเมอร์หน่วงกลับทาง 0.5–2 s ให้มอเตอร์ชะลอ

## สตาร์-เดลต้าด้วย PLC กลาง

รูป 1 · เอาต์พุตสั่งคอยล์ผ่านหน้าสัมผัส NC ของคอนแทกเตอร์ตรงข้าม (ฮาร์ดไวร์) · อินพุตรับปุ่ม โอเวอร์โหลด และป้อนกลับทั้งสามตัว

M4 Star–delta sequence ลำดับสตาร์-เดลต้าในโปรแกรม

$$K_Y = \text{Run}\,\overline{T_Y}\,\overline{K_\Delta} \quad K_1 = \text{Run}\,(K_Y + K_1) \quad K_\Delta = \text{Run}\,\text{TON}(T_Y,\ t_{dead})\,\overline{K_Y}\,\overline{FB_Y}$$

(* Structured Text: star–delta with feedback check *)
Run := (PB_Start OR Run) AND PB_Stop_NC AND OL_NC AND NOT Fault;
TY(IN := Run, PT := T#6S); // เวลาช่วงสตาร์
KY := Run AND NOT TY.Q AND NOT KD; // K2 สตาร์
K1 := Run AND (FB_Y OR K1); // K1 หลัง เมื่อสตาร์ดูดจริง
TDead(IN := TY.Q AND NOT FB_Y, PT := T#80MS); // รอ K2 ปล่อยจริงแล้วนับช่วงตาย
KD := Run AND TDead.Q; // K3 เดลต้า
TChk(IN := (K1 XOR FB_1) OR (KY XOR FB_Y) OR (KD XOR FB_D), PT := T#1S);
IF TChk.Q OR (FB_Y AND FB_D) THEN Fault := TRUE; END_IF
สังเกต: ช่วงตายเริ่มนับเมื่อ ป้อนกลับ ของ K2 ยืนยันว่าปล่อยแล้ว ไม่ใช่เมื่อสั่งปล่อย — ป้องกันกรณีหน้าสัมผัส K2 ค้าง นี่คือสิ่งที่วงจรรีเลย์ธรรมดาทำไม่ได้ ซิมูเลเตอร์ด้านล่างเป็นรุ่นย่อที่ไม่มีป้อนกลับ

### ทดสอบลำดับในซิมูเลเตอร์และตอบคำถาม

- กด START: บันทึกลำดับที่ Q0.1 (Y) และ Q0.0 (K1) ติด — ทำไม Q0.1 ต้องติดก่อน? (เพื่อให้จุดสตาร์ต่อเสร็จก่อนจ่ายไฟเข้าขดลวด)

- ดูแถบ ET ของ T1 และ T2: ช่วงที่ Q0.1 ดับแต่ Q0.2 ยังไม่ติดยาวเท่าไร? (80 ms = PT ของ T2)

- แก้รัง Q0.1 ลบเงื่อนไข !Q0.2 แล้วโหลดใหม่ ระบบยังทำงานไหม และทำไมอินเตอร์ล็อกนี้ยังควรอยู่?

## คำถามที่พบบ่อย

ใช้ PLC แล้วยังต้องมีหน้าสัมผัสช่วยอินเตอร์ล็อกในวงจรคอยล์อีกไหม?
ต้องมี อินเตอร์ล็อกที่ป้องกันลัดวงจร (K1/K2 กลับทาง K2/K3 สตาร์-เดลต้า) ต้องทำงานได้แม้ PLC เสีย เอาต์พุตทรานซิสเตอร์ลัดค้าง หรือมีคนสั่ง force บิต การใส่หน้าสัมผัส NC ของคอนแทกเตอร์ตรงข้ามอนุกรมกับคอยล์และอินเตอร์ล็อกทางกลจึงยังจำเป็น โปรแกรมเป็นชั้นเพิ่มเติม ไม่ใช่ชั้นเดียว

ต่อโอเวอร์โหลดเข้า PLC อย่างเดียวได้ไหม?
ทำได้ในทางเทคนิค แต่แนวปฏิบัติที่ดีคือให้ 95-96 อนุกรมกับคอยล์คอนแทกเตอร์โดยตรง (ตัดได้แม้ PLC ค้าง) และนำ 97-98 หรือหน้าสัมผัสช่วยเข้า PLC เพื่อแสดงสถานะและบันทึกเหตุการณ์
