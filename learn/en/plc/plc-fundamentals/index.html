    What Is a PLC: CPU, Memory, I/O, the Scan Cycle, Scan Time, the IEC 61131 Standard and Choosing a PLC

    In 1968 General Motors' Hydra-Matic transmission plant wanted to stop rewiring relay panels every time the car models changed. That brief produced the first PLC (the Modicon 084). The core idea is unchanged today: a computer built to survive the factory floor, which reads inputs from switches and sensors, decides with a program an electrician can read, and drives outputs — repeating predictably, without end.

    By Ajarn ModUpdated 14 Oct 2026
    In 30 seconds
    • PLC = power supply + CPU + memory + I/O modules + communication ports
    • One scan: read inputs into the image → run the program top to bottom → write outputs → system tasks
    • Typical scan time 1–20 ms · worst-case response ≈ input delay + 2 scans + output delay
    • Its strength is robustness and deterministic behaviour, not speed

    The scan cycle Intermediate

    A PLC does not “watch” its inputs continuously. At the start of each scan it takes a snapshot of every input terminal into the input image table, then runs the program rung by rung from top to bottom, reading from that snapshot. Coil results are written to the output image, which is sent to the output terminals all at once at the end of the scan. Working this way means input values cannot change part-way through a scan, so the result is predictable.

    Example F-1

    A conveyor runs at 1.2 m/s; 30 mm parts pass a photoelectric sensor; PLC scan 10 ms, input filter 3 ms

    1. Time the part blocks the sensor: t=0.030/1.2=25t = 0.030/1.2 = 25t=0.030/1.2=25 ms

    2. F4: must exceed 10+3=1310 + 3 = 1310+3=13 ms → 25 ms is caught ✓ (almost a 2× margin)

    3. If the conveyor speeds up to 3 m/s: t=10t = 10t=10 ms < 13 ms → parts may be missed; use a high-speed input or a hardware counter

    4. F3: the time from a part reaching the sensor to the air-jet reject (transistor output 0.1 ms + solenoid 15 ms) is at worst ≈ 3 + 20 + 0.1 + 15 = 38 ms → the part travels 46 mm in that time, so mount the air nozzle this far beyond the sensor

    The IEC 61131 standard Intermediate

    IEC 61131 makes PLC knowledge transferable across brands. The parts electricians and engineers use most:

    • Part 2 (equipment): 24 VDC input Types 1/2/3, ON/OFF voltage ranges, EMC tests — details in I/O wiring
    • Part 3 (languages): LD, FBD, ST, SFC (and IL, deprecated in the 2013 edition), data types, standard timers and counters — see IEC 61131-3 languages

    How to choose a PLC Intermediate

    F5 I/O count with spare

    NI/O=⌈1.2 Nrequired⌉(15–25 % spare)N_{I/O} = \left\lceil 1.2\,N_{required} \right\rceil \quad (\text{15–25 \% spare})NI/O​=⌈1.2Nrequired​⌉(15–25 % spare)
    1. Make an I/O list: count digital and analog inputs and outputs and high-speed inputs, with their types (PNP/NPN, 4–20 mA)
    2. The required response time (F3) and special functions (PID, counters, motion)
    3. Communication with the HMIs, drives and SCADA systems already in the plant
    4. Safety: is a safety PLC or safety relay needed?
    5. Environment: panel temperature, humidity, vibration
    6. Plant standards and spares on hand — a brand the maintenance staff already know is often better value than a cheaper one

    Frequently asked questions

    If a button is pressed for less than the scan time, will the PLC see it?

    Possibly not. Inputs are read once at the start of each scan, so a pulse shorter than the scan time plus the input filter time can appear and disappear between two reads. Fast signals (encoders, high-speed part-counting sensors) need high-speed inputs, hardware counters or interrupts.

    Why does writing the same coil in two places make the program misbehave?

    Because the PLC executes from top to bottom, the value written by the lower coil overwrites the value from the upper one before the outputs are sent at the end of the scan. The upper coil appears not to work (double-coil syndrome). Combine the conditions into a single rung, or use SET/RESET deliberately.

    Site Home คลังความรู้ Articles: Laplace, vectors, power factor & more ฟังก์ชันและกราฟ สูตรและตารางตรีโกณมิติ ลิมิตและความต่อเนื่อง ลำดับและอนุกรม · อุปนัย อนุพันธ์: สูตรและวิธีทำ การประยุกต์อนุพันธ์ทางวิศวกรรม สูตรอินทิเกรตและวิธีทำ การประยุกต์อินทิกรัลทางวิศวกรรม เวกเตอร์: แรงลัพธ์ สนาม เฟสเซอร์ สตูดิโอเวกเตอร์ 3 มิติ แรงลัพธ์ด้วยกฎไซน์-โคไซน์ เฟสเซอร์และวงจรไฟฟ้ากระแสสลับ แล็บกลศาสตร์เสมือน (ฟิสิกส์ 1) แล็บสนามไฟฟ้า-แม่เหล็ก (ฟิสิกส์ 2) พีชคณิตเชิงเส้น: เมทริกซ์ ดีเทอร์มิแนนต์ ค่าเฉพาะ แล็บเมทริกซ์: เครื่องคิดเลขแสดงวิธีทำ การประยุกต์พีชคณิตเชิงเส้นทางวิศวกรรม การแปลงลาปลาซ: ตารางและ ROC แผนภาพโพล-ซีโร่และ ROC คุณสมบัติการแปลงลาปลาซ การแปลงลาปลาซผกผัน (Inverse Laplace) แล็บระบบอันดับหนึ่ง แล็บระบบอันดับสอง แล็บสัญญาณเบื้องต้น อนุกรมฟูเรียร์และการวิเคราะห์ฮาร์มอนิก แล็บวิเคราะห์ฮาร์มอนิก: สโคป + เครื่องวิเคราะห์กำลังไฟฟ้า ตารางอนุกรมฟูเรียร์ของรูปคลื่น THD เพาเวอร์แฟกเตอร์ และ IEEE 519 อิเล็กทรอนิกส์กำลัง: บั๊ก บูสต์ ชุค ตัวชดเชย แล็บจำลองคอนเวอร์เตอร์ DC-DC ออนไลน์ แบบจำลองเฉลี่ยและสเตตสเปซของบั๊กคอนเวอร์เตอร์ แล็บออกแบบบั๊ก: เลือกชิ้นส่วนและโปรแกรมโหลด ออกแบบระบบโซลาร์เซลล์: แผง สตริง แบตเตอรี่ MPPT อินเวอร์เตอร์ เครื่องมือออกแบบโซลาร์เซลล์ออนไลน์ โซลาร์เซลล์จ่ายแอร์ ปั๊มน้ำโซลาร์และโซลาร์เพื่อการเกษตร ระบบชาร์จรถยนต์ไฟฟ้าที่บ้าน: ชาร์จช้า ชาร์จเร็ว ไฟบ้าน โซลาร์เซลล์ แอร์ และรถ EV ในบ้านเดียว ระบบไฟฟ้ากำลังและระบบป้องกัน (ปูพื้น) ประสานรีเลย์กระแสเกิน TCC เพาเวอร์แฟกเตอร์ เข้าใจได้ทุกระดับ ซิมูเลเตอร์เพาเวอร์แฟกเตอร์ เซนเซอร์และทรานส์ดิวเซอร์: เครื่องมือวัดคุมอุตสาหกรรม แล็บวัดคุมเสมือน 4–20 mA PID 4–20 mA และ HART Modbus RTU และ TCP เครื่องมือแปลงหน่วย แล็บเครื่องกำเนิดสัญญาณและออสซิลโลสโคป ออสซิลโลสโคปจำลองออนไลน์ แล็บออปแอมป์ ระบบควบคุม: ป้อนกลับ เสถียรภาพ รูทโลคัส โบด PID เกณฑ์เสถียรภาพของเราท์–เฮอร์วิตซ์ วาดรูทโลคัสด้วยมือ ตัวควบคุม PID และการจูน เมคาทรอนิกส์และโรโบติกส์ Lesson editor About Ajarn Mod
