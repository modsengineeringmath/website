    อุปนัยแบบเข้ม (Strong Induction): หลักการ จำนวนกรณีฐาน ตัวอย่างเข้มข้น 17 ข้อ และแล็บฝึกพิสูจน์

    อุปนัยธรรมดาบอกว่า “ถ้าตัวก่อนหน้าล้ม ตัวถัดไปล้ม” แต่โจทย์จริงจำนวนมากต้องการมากกว่านั้น: ฟีโบนัชชีต้องรู้สองตัวก่อนหน้า แสตมป์ 3 บาทย้อนกลับสามขั้น จำนวนเต็มแตกเป็นตัวประกอบที่เล็กกว่าเท่าไรก็ได้ อุปนัยแบบเข้มให้เราสมมติทุกกรณีที่เล็กกว่าพร้อมกัน หน้านี้พาฝึกตั้งแต่หลักการ การนับกรณีฐาน ไปจนถึงอัลกอริทึมและระบบควบคุม ด้วยตัวอย่าง 17 ข้อและแล็บที่ลองทำได้บนมือถือ

    นึกถึงแถวโดมิโน อุปนัยธรรมดา (weak / ordinary induction) รับประกันว่า “ตัวที่ k ล้มแล้วชนตัวที่ k + 1” ส่วนอุปนัยแบบเข้ม (strong / complete induction) รับประกันว่า “ถ้าตัวที่ n0n_0n0​ ถึง n−1n - 1n−1 ล้มหมดแล้ว ตัวที่ n ก็ล้ม” เปรียบได้กับโดมิโนที่ต้องถูกชนจากหลายตัวพร้อมกัน หรือจากตัวที่อยู่ห่างออกไป

    เท่ากับจำนวนขั้นที่ขั้นอุปนัยย้อนกลับไกลที่สุด ถ้าใช้ P(n−1)P(n-1)P(n−1) และ P(n−2)P(n-2)P(n−2) ต้องมีกรณีฐานสองตัว (เช่น F1F_1F1​ และ F2F_2F2​) ถ้าใช้ P(n−4)P(n-4)P(n−4) แบบโจทย์แสตมป์ 4 และ 5 บาทต้องมีสี่ตัว ถ้าขาดไปแม้ตัวเดียว ทั้งบทพิสูจน์ใช้ไม่ได้

    พิสูจน์ว่าทุกราคาตั้งแต่ 8 บาทขึ้นไปรวมได้ด้วยแสตมป์ 3 และ 5 บาทอย่างไร?

    ทำไมการพิสูจน์ว่าทุกจำนวนเต็มเป็นผลคูณของจำนวนเฉพาะต้องใช้อุปนัยแบบเข้ม?

    เพราะถ้า n ไม่เป็นจำนวนเฉพาะ n = ab โดย a และ b เล็กกว่า n แต่ไม่ใช่ n − 1 การรู้ว่า n − 1 เป็นผลคูณของจำนวนเฉพาะไม่ช่วยอะไรเลย ต้องสมมติว่าทุกจำนวนที่เล็กกว่า n เป็นผลคูณของจำนวนเฉพาะ จึงใช้สมมติฐานกับ a และ b ได้

    อุปนัยแบบเข้มใช้ในงานวิศวกรรมหรือวิทยาการคอมพิวเตอร์อย่างไร?

    ใช้พิสูจน์ความถูกต้องและเวลาทำงานของอัลกอริทึมแบบแบ่งแล้วเอาชนะ (เช่น merge sort ใช้การเปรียบเทียบไม่เกิน n⌈log⁡2n⌉n\lceil\log_2 n\rceiln⌈log2​n⌉ ครั้ง binary search ใช้ ⌊log⁡2n⌋+1\lfloor\log_2 n\rfloor + 1⌊log2​n⌋+1 รอบ) พิสูจน์สูตรปิดของลำดับเวียนเกิดในตัวกรองดิจิทัล และพิสูจน์ว่าค่าความคลาดในระบบควบคุมดิจิทัลลดลงแบบเรขาคณิต ∣en∣≤Crn|e_n| \le Cr^n∣en​∣≤Crn
